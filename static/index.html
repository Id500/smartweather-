🔬 How the Machine Learning Pipeline Operates

  1. Data Ingestion: Up to 500 days of real daily observations (maximum, minimum, and mean temperatures, precipitation, wind speed, relative humidity, and surface pressure) are retrieved from Open-Meteo's historical reanalysis archive.
  2. Temporal Feature Engineering: We engineer autoregressive lag features (lag 1, 2, 3, 7 days), rolling 7-day temperature trends, diurnal range (Max - Min), and cyclical sine/cosine encodings of the day-of-year to capture seasonal oscillation without data leakage.
  3. Strict Chronological Split: We partition the historical dataset chronologically (earliest 80% for training, most recent 20% held out for testing). Zero future data is ever leaked to the training algorithm.
  4. Ensemble Training: An ensemble of 120 decision trees (Random Forest Regressor) with tree-depth regularization learns non-linear microclimate dependencies.
  5. Benchmark Baseline: The model is continuously benchmarked against a Persistence Baseline (predicting tomorrow's max equals today's max).
* Notice: The ML prediction is an experimental demonstration model designed for hackathon evaluation and should be compared against the official physics-based numerical model.

🛠️ Technology Stack

  • Backend: Netlify Functions with RESTful JSON endpoints
  • Machine Learning: Random Forest Regressor, 120 trees
  • Data Crunching: Pandas & NumPy (Temporal Lag Feature Engineering)
  • Frontend & Charts: Modern Vanilla HTML5, CSS Glassmorphism & Plotly.js
  • Telemetry: Open-Meteo REST APIs (Geocoding, Forecast, Archive)
  • Model Serialization: Joblib + Memory Caching

🌐 Open-Meteo REST Endpoints

  • geocoding-api.open-meteo.com/v1/search: Worldwide fuzzy coordinate lookup
  • api.open-meteo.com/v1/forecast: Real-time sensor feeds & 7-day outlook
  • archive-api.open-meteo.com/v1/archive: Historical observations for ML training
  • Zero API Keys Required: Fully open, rate-limited and cached respectfully
